Problem-solving

Real troubleshooting cases: problem, possible causes, diagnosis, solution, lesson.

Problem: A computer cannot connect to the network or the internet.

Possible causes: loose or unplugged ethernet cable, damaged cable, disabled adapter, driver problem, wrong IP settings, or a router, switch or DNS problem.

Diagnosis: checked that the ethernet cable was connected directly to the CPU's LAN port, then ran the Windows network troubleshooter. If the problem remained, ran ipconfig /all and used ping on the gateway and on 8.8.8.8.

Solution: made sure the ethernet cable was plugged directly into the CPU and ran the troubleshooter until the connection was restored.

Lesson learned: check the physical connection first. Every time, confirm the ethernet cable is connected directly to the CPU, then run the built-in troubleshooter before changing any settings.

Problem: The device shows "Connected" but there is no internet.

Possible causes: a problem with the IP address from the router, an old or corrupted DNS cache, a DNS server that is not responding, or a gateway or router problem.

Diagnosis: the connection was up but websites would not load, which points to the IP address or name resolution (DNS) rather than the cable or Wi-Fi link. Pinging an IP address such as 8.8.8.8 and then a website name shows whether DNS is the failing part.

Solution: renewed the IP address with ipconfig /renew, cleared the local DNS resolver cache with ipconfig /flushdns, then switched the device to a stable public DNS server (for example 8.8.8.8) to restore name resolution.

Lesson learned: when a device is connected but has no internet, work through the IP address first, then the DNS cache, then the DNS server.

Problem: A computer has no internet or an IP problem, such as a limited connection or an address starting with 169.254.

Possible causes: wrong or missing IP settings, DHCP not giving an address, duplicate IP address, loose cable, or a router problem.

Diagnosis: checked the cable and adapter, ran ipconfig /all to read the IP address, subnet mask, gateway and DNS, then used ping to test the gateway and then 8.8.8.8.

Solution: set the adapter to obtain an IP automatically, ran ipconfig /release and ipconfig /renew, and restarted the adapter or router. If the address was a duplicate, gave the computer a different IP. Confirmed the fix with ping.

Lesson learned: read the IP settings first, then test one step at a time, from the cable to the gateway to the internet.

Problem: The computer is slow or freezing.

Possible causes: an application using too much CPU, memory or disk, too many programs running, or a background process that is stuck.

Diagnosis: pressed Ctrl + Shift + Esc to open Task Manager, then clicked the CPU, Memory and Disk column headers to sort and see which processes use the highest percentage.

Solution: right-clicked the non-essential application using a large share of the resources and selected End Task.

Lesson learned: sort Task Manager by resource use to find the real cause before restarting or reinstalling. End only non-essential applications, and save your work first.

Problem: The printer is not printing or cannot be found.

Possible causes: loose or damaged cable, printer needs a restart, printer IP changed, network problem between the computer and the printer, or a driver or print queue problem.

Diagnosis: checked the printer cable and restarted the printer. For a network printer, used ping on the printer's IP address. A reply means the network is fine, so the problem is the driver or print queue. "Request timed out" (RTO) means a network connection problem.

Solution: reseated or replaced the cable and restarted the printer. When the ping showed RTO, checked the switch or Wi-Fi connection and the printer's IP. Printed a test page once the ping replied.

Lesson learned: start with the simplest checks, cable and restart, then use ping to tell whether the problem is the network or the printer.

Cybersecurity case study: SQL injection

A defensive look at one of the most common web application weaknesses, and how developers prevent it.

1. What is the vulnerability?

SQL injection happens when an application places text typed by a user directly inside a database query. The database cannot tell the developer's query apart from the user's input, so SQL code written by an attacker can run as part of the query.

3. What are the risks?

  • Logging in without the correct password.
  • Reading private data such as accounts and personal information.
  • Changing or deleting records.
  • Loss of trust and legal problems, for example under the Data Privacy Act of 2012 in the Philippines.

2. How can it happen?

It happens when code builds a query by joining strings. In a help desk system, the login form and the ticket search box are the first places to check. If someone types SQL code, such as ' OR '1'='1, into the username box, that text becomes part of the query and can change its meaning, for example by letting someone in without a valid password.

Vulnerable: do not use 
$sql = "SELECT * FROM users WHERE username = '"
     . $_POST['user'] . "' AND password = '"
     . $_POST['pass'] . "'";
$result = $conn->query($sql);
Safe: prepared statement 
$stmt = $pdo->prepare(
  "SELECT * FROM users WHERE username = ?");
$stmt->execute([$_POST['user']]);
$user = $stmt->fetch();
if ($user && password_verify($_POST['pass'],
    $user['password_hash'])) { /* login OK */ }

With a prepared statement, the query is fixed first and the user's text is sent separately as data, so it can never become part of the query.

4. How can developers prevent it?

  • Use prepared statements (parameterized queries) for every query that includes user input.
  • Validate input for type, length and allowed characters.
  • Store passwords as hashes, never as plain text.
  • Give the application's database account only the permissions it needs.
  • Show users a generic error message and keep detailed database errors in private logs.

5. What security practices should be implemented?

  • Test only on your own system or a local copy, never on systems you do not own.
  • Keep the software, frameworks and libraries updated.
  • Log and monitor failed logins and unusual activity, and limit login attempts.
  • Use HTTPS, keep regular backups, and review code before release.
  • Follow the OWASP Top 10 guidance for secure development.

Technical interview study notes

What happens when you type a URL in a browser?

The browser asks a DNS server for the site's IP address, opens a TCP connection to it, sends an HTTP or HTTPS request, and the server sends the page back. If names do not resolve, pages do not load, which is why my "connected, no internet" case checked DNS.

What is subnetting?

Dividing a network into smaller networks. A /24 has the mask 255.255.255.0 and 254 usable host addresses. My subnet calculator shows the network, broadcast and host range for any address and prefix.

What does DHCP do?

It gives devices an IP address, mask, gateway and DNS automatically (Discover, Offer, Request, Acknowledge). When it fails, a Windows PC may show a 169.254.x.x address, which is why ipconfig /renew was part of my fix.

What is the difference between ping and tracert?

Ping tests whether a device replies and how fast. "Request timed out" means no reply, as in my printer case. Tracert shows each router hop on the path, so it shows where the connection stops.

What does a SQL JOIN do?

It combines rows from two tables using a related column. For example, my ticket queries join tickets to categories to count tickets per category.

How do you prevent SQL injection?

Use prepared statements for every query with user input, validate input, hash passwords, give the database account only the permissions it needs, and hide detailed errors from users.
